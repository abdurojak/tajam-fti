# TAJAM FTI Implementation Plan

**Goal:** Aplikasi Next.js lokal yang menerapkan template perencanaan konten dengan status Draf, Terbit, Batal.
**Architecture:** App Router dengan API JSON, SQLite lokal, validasi domain bersama, UI React responsif. Excel dibaca di browser; hanya data hasil validasi dikirim ke server. Semua aktivitas lokal tanpa kredensial cloud.
**Tech Stack:** Next.js, TypeScript, React, better-sqlite3, ExcelJS, Lucide, Vitest.

## Urutan pelaksanaan
- [x] Siapkan package.json, TypeScript, Next config, gitignore. `npm install` harus berhasil.
- [x] Buat `tests/domain.test.ts` dengan kasus status yang disepakati, tanggal invalid, tanggal sama sebagai peringatan, URL aman, dan status approval lama ditolak. Jalankan `npm test` sebelum `src/lib/domain.ts` diimplementasikan; lalu implementasikan hingga lulus.
- [x] Buat `tests/workbook.test.ts` untuk header template, serial tanggal Excel, baris kosong, enum salah, duplikat, formula yang tidak dieksekusi, serta export/import round-trip. Implementasikan `src/lib/workbook.ts` dan uji kembali.
- [x] Buat `tests/store.test.ts` untuk CRUD, impor transaksional dan duplikat, serta persistensi setelah menutup koneksi. Implementasikan `src/lib/store.ts`, `src/app/api/content/route.ts`, `src/app/api/content/[id]/route.ts`, `src/app/api/import/route.ts`.
- [x] Bangun `src/components/planner.tsx` sebagai pengatur state dan navigasi; komponen dashboard, kalender, tabel, formulir, impor, dan laporan dipisah. State pencarian/filter berlaku konsisten pada data dan ekspor. Semua error server tampil di UI.
- [x] Terapkan `src/app/globals.css`: sidebar gelap, aksen lime, halaman putih hangat, tabel lega, keyboard focus jelas, layout mobile, dan CSS print untuk PDF.
- [x] Jalankan `npm test`, `npm run typecheck`, `npm run build`. Uji API pada database sementara agar tidak mengisi data pengguna. Uji browser: tambah, edit, filter, kalender, arsip, impor, ekspor; lihat screenshot desktop/mobile.
- [x] Tulis README, jalankan server lokal, buka aplikasi di panel Codex, catat hasil dan batas integrasi Google Calendar.

## Kriteria penerimaan
Semua 12 kolom dipertahankan; dropdown sesuai referensi dengan status baru. Baris kosong diabaikan, kesalahan impor ditunjukkan dengan nomor baris, impor invalid tidak menyimpan sebagian data. Batal terpisah di arsip. Acara dan upload tampil berbeda di kalender. Database bertahan setelah restart. Ekspor Excel kompatibel untuk diimpor ulang. PDF dapat diunduh langsung; dialog cetak browser juga tersedia. Ekspor ICS dinyatakan manual, bukan sinkronisasi Google otomatis.

## Pengujian perilaku inti
`validateContent({...valid, status: 'Disetujui'}).errors.status` harus ada.
`validateContent({...valid, eventDate: valid.uploadDate}).warnings` harus berisi peringatan tanpa error.
`store.import([valid, valid])` harus menghasilkan satu tambahan dan satu duplikat.
`parseWorkbook(await createWorkbook([valid]))` harus mengembalikan data ekuivalen.

## Catatan pelaksanaan
Pengguna telah meminta melanjutkan implementasi. Pekerjaan dilakukan langsung di folder proyek kosong yang ditentukan pengguna, tanpa deployment atau publikasi eksternal.
